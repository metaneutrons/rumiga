# M1-003: Canonical Core Primitive Boundary

- Status: Unreleased
- Change type: Changed
- Task: M1-003
- Audience: Embedded integrators and maintainers

## Summary

The canonical `rumiga-core` now enforces portable `core` and `alloc` primitives
even when built with the default desktop profile. The MAC-address validation
error implements the shared `core::error::Error` trait, and core memory handoff
uses `core::mem`.

## User And Operator Impact

Desktop emulator behavior is unchanged. Embedded consumers can use
`MacAddressError` through the portable error trait without selecting `std`.

## Compatibility And Migration

No feature flags or public desktop APIs change. Core contributors must use
`core` or `alloc` when an equivalent exists; strict Clippy rejects accidental
standard-library replacements in both explicit runtime profiles.

## Verification

The host gate now runs strict Clippy for `rumiga-core` under `std` and `no_std`,
then executes the complete workspace test and documentation suite. The portable
gate continues to build the stock core as an optimized RISC-V release, while
the host gate verifies the same stock `no_std` graph with the declared Rust 1.85
MSRV. Pull-request run `31961164165` and final `main` run `31961501684` passed
all required jobs; their governance artifacts were independently checksum
verified.

## Known Limitations

File-backed tracing and background blitter threads remain host-only services.
Their injected-service and deterministic-owner replacements are M1-004 and
M1-005.
