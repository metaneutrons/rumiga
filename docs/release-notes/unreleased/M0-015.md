# M0-015: Node Pin On The Current Release Line

- Status: Unreleased
- Change type: Changed
- Task: M0-015
- Audience: Contributors and maintainers

## Summary

The Node pin moves from `24.19.0` to `26.7.0` and npm from `11.17.0` to `11.19.0`.
`@types/node` moves to `^26.2.0` so the type definitions describe the runtime the
web build actually uses.

## User And Operator Impact

Contributors need Node `26.7.0` and npm `11.19.0`. `.node-version` carries the
value for version managers, and the host gate rejects a mismatch before building.

No shipped artifact changes. Node is a build-time tool that produces the static
export embedded into the desktop binary and later the firmware; no Node runtime
ships in the product.

## Compatibility And Migration

Install Node `26.7.0`, then reinstall the web dependencies. The lockfile was
regenerated on the new runtime.

`@types/node` was previously `^22.20.1`, a major behind the pinned runtime, so some
Node type definitions did not match the version in use. Code that relied on the
older definitions may now see accurate types where it previously saw stale ones.

## Verification

On Node `26.7.0` with npm `11.19.0`, `npm ci` installs 355 packages,
`npm run lint` is clean, and `npm run build` produces the five static routes. The
cross-file pin test proves that `toolchain/manifest.toml`, `.node-version`, and
`web/package.json` agree.

## Known Limitations

Node 26 is not a long-term-support line at the time of this change. The release
index lists it as `lts: false`, with support expected around October 2026. This is a
deliberate exception recorded in `TOOLCHAIN.md` and ADR-0009, taken because Node
never ships in the product and because staying on 24 would require stepping the pin
twice within months. Until 26 becomes LTS, pin refreshes may be needed more often
than for the other toolchain entries.
