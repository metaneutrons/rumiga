# M1-004: Injected Diagnostic Trace Sink

- Status: Unreleased
- Change type: Changed
- Task: M1-004
- Audience: Embedded integrators and maintainers

## Summary

CPU tracing no longer creates files inside `rumiga-core`. The core formats trace
records and writes them to an injected `TraceSink`; the desktop adapter owns
file creation, buffering, and the line terminator. Tracing is therefore
available in both runtime profiles instead of only under `std`.

## User And Operator Impact

`--trace-cpu` and `--trace-limit` behave as before. Trace files contain the same
bytes, and the capture manifest reports the same `trace_count` value. Trace
output is now flushed explicitly when the emulator loop or a capture run ends,
so a trace file no longer depends on drop order for durability.

## Compatibility And Migration

The core's public tracing API changes. `enable_cpu_trace()`, the `trace_writer`
and `trace_limit` fields, and the public `trace_count` field are removed.
Consumers attach a sink instead:

```rust
use rumiga_platform_desktop::FileTraceSink;

let sink = FileTraceSink::create(path)?;
emulator.set_trace_sink(Box::new(sink), limit);
// ...
emulator.flush_trace();
let recorded = emulator.trace_count();
```

Embedded integrators implement `rumiga_platform::TraceSink` for their transport.
Records arrive without a line terminator, and both trait methods are infallible,
so a transport absorbs its own errors. `rumiga-core` now depends on
`rumiga-platform`.

## Verification

Core tests use an in-memory sink and assert golden records captured from the
previous file-writing implementation. They pass under `std` and `no_std`, which
proves byte compatibility without the core creating a file, and they also cover
the trace limit, the count reset on attach, detach behavior, and the emulator's
`Send` property. A desktop adapter test covers real file creation, truncation,
the `\n` terminator, and host error reporting.

## Known Limitations

Only CPU instruction tracing uses the sink. A structured logging contract with
redaction and bounded transport is later platform work. Host threads and CPU
affinity remain in the desktop blitter path; removing them is M1-005.
