# M1-006: Emulated Time And Host Pacing

- Status: Unreleased
- Change type: Added
- Task: M1-006
- Audience: Embedded integrators and maintainers

## Summary

Host time now lives in a platform `Clock` contract that the product shell owns. The
core declares its emulated frame duration, the desktop paces against it, and the
reported frame rate is measured instead of asserted.

## User And Operator Impact

The desktop frame loop paces deliberately. It previously ran flat out and slept 16 ms
only when no frame was ready, so nothing enforced the 50 frames per second stated as
the PAL target.

The REST `fps` field is now measured over a 500 ms window. It previously reported a
hardcoded `50.0`, publishing a constant as if it were a measurement.

Emulated frame duration comes from the colour clock rather than a rounded rate. A PAL
frame is 19.968 ms, not 20 ms; the difference is 32 microseconds per frame, about
1.6 ms per second.

## Compatibility And Migration

`rumiga-platform` gains a `Clock` trait. Embedded integrators implement it for their
host: `now` must be monotonic, and `pace` must return the time actually spent rather
than the time requested.

`Emulator::frame_period` is new. A shell should pace against it rather than against a
constant of its own, so pacing stays correct when the video standard becomes
selectable.

The headless capture path is unchanged and produces the same digests as before, so
evidence generation is independent of host timing.

## Verification

The frame period is pinned in both runtime profiles. Four desktop contract tests cover
monotonicity, that `pace` never reports less than requested, that a zero request
yields, and that `now` advances across a `pace` call.

The core is prevented from naming a host clock type by a Clippy `disallowed_types`
configuration. This was verified by temporarily adding a `std`-gated function returning
`Instant`, which the lint rejected, so the ban also covers the feature-gated path where
the trace file and the blitter thread had previously hidden.

## Known Limitations

Whether the desktop sustains the paced rate under load is not established. The loop now
requests the correct period and reports what it achieves, which is the precondition for
that measurement rather than the measurement itself.

The video standard is still fixed to PAL. NTSC geometry, colour clock, and Agnus
identification are M1-013; until then `--ntsc` continues to print a warning rather than
changing frame timing.
