# M0-014: Merged Firmware Image Contract

- Status: Unreleased
- Change type: Fixed
- Task: M0-014
- Audience: Firmware integrators and maintainers

## Summary

The merged ESP32-P4 flash image now carries the ESP-IDF bootloader, the ESP-IDF
partition table, and the flash geometry declared by the resolved `sdkconfig`, and
the evidence task verifies that it does.

## User And Operator Impact

Every firmware bundle published before this change contained a merged image that
contradicted its own configuration evidence. The image declared a 4 MB flash
geometry at 40 MHz with a 3.94 MB application partition, while the `sdkconfig`,
flasher arguments, bootloader, and partition table in the same bundle declared
16 MB at 80 MHz with a 1 MB partition. Anyone who flashed a published merged
image would have written a bootloader that was not built from the pinned
configuration.

## Compatibility And Migration

Discard merged images from earlier bundles. The standalone `bootloader.bin`,
`partition-table.bin`, and `flasher_args.json` in those bundles were always
correct and can still be used.

The `rumiga.firmware.build.v1` manifest gains a `merged_image` section. The
addition is additive, so existing readers are unaffected; this follows the
established practice for `rumiga.capture.v1`, which also gained sections without
a version change.

## Verification

The evidence task asserts that the bootloader region at `0x2000` and the
partition-table region at `0x8000` are byte identical to the standalone
artifacts, which transitively pins the image header, and that the application
fits its declared partition. Six unit tests cover the partition-table decoder,
the region bounds check, and the configuration value mapping in both directions.

The hosted bundle from pull-request run `32012799294` was downloaded and checked
independently: all nine payload checksums pass, both embedded regions match, the
image header encodes 16 MB at 80 MHz, and the application occupies 175,040 of
1,048,576 partition bytes.

## Known Limitations

The partition layout itself is unchanged. It remains the stock ESP-IDF
single-application table with no OTA slots and no data partition beyond `nvs`
and `phy_init`. Defining the product layout is M2-003. Flashing, booting, and
peripheral behavior remain unproven; the manifest still excludes those claims.
