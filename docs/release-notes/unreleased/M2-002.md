# M2-002: Reproducible Firmware Build

- Status: Unreleased
- Change type: Fixed
- Task: M2-002
- Audience: Embedded integrators and maintainers

## Summary

The firmware images carry a build stamp derived from the commit rather than the clock, and
the build now checks that on every run instead of assuming it. Building the same revision
twice produces the same bytes, which a new on-demand comparison proves.

## User And Operator Impact

An image can be dated to its commit. The application and bootloader descriptors record the
HEAD commit time, and the application descriptor records `git describe`, so a flashed unit
identifies the source it came from.

Nothing about the emulated machine changes. No image content changes either; this makes an
existing property checkable.

The evidence bundle gains a `determinism` section recording the stamp and its source, the
descriptor offsets, whether the merged image's recorded ELF digest matches the packaged
ELF, and how many random link paths the map contains.

## Compatibility And Migration

`rumiga.firmware.build.v1` gains an additive `determinism` section, which follows the
practice M0-014 set when it added `merged_image` without a version bump. Readers of the
existing sections are unaffected.

The manifest's `claims` list gains `commit-derived-build-stamp` and one of
`rebuild-byte-identical` or `rebuild-not-compared`. `exclusions` gains
`linker-map-carries-a-random-link-path`.

`cargo xtask firmware-evidence` accepts `--verify-rebuild`. Without it the behaviour is
unchanged apart from the new checks.

## Verification

Every run now fails if the application descriptor's date and time are not the HEAD commit
time rendered as GCC renders it, if the bootloader descriptor disagrees, if the descriptor
version is not `git describe --always --tags --dirty`, or if the merged image's
`app_elf_sha256` is not the packaged ELF's digest.

The check was proved to fire, not assumed to. Removing the `SOURCE_DATE_EPOCH` export made
the task stop with the descriptor reporting `Aug 18 2026 23:51:13` against a commit time of
`Aug 18 2026 21:35:22`, which is the builder's local clock leaking into the image. The
export was restored and the restoration verified by search.

`cargo xtask firmware-evidence --verify-rebuild` builds one revision twice from an emptied
build tree and reports the bootloader, partition table, ELF, merged image, size report,
`sdkconfig`, and flasher arguments byte-identical, with the map identical after the
anchored normalization and nothing differing. The stamp both runs recorded equalled that
commit's timestamp to the second.

Unit tests cover the stamp rendering, including the space-padded single-digit day that a
naive format would get wrong, the anchored link-path scan against near misses a loose match
would take, that normalization does not hide a section-address change, and that an image
must carry exactly one application descriptor. They run in the host gate on both legs.

## Known Limitations

The rebuild comparison is not a gate. Running it on every pull request would roughly double
the firmware job, from about six and a half minutes to twelve, to re-derive a property
whose one known input the cheap check already pins. The continuous claim is therefore that
the stamp is commit-derived, not that two builds were compared, and the manifest says which
of the two a given bundle carries.

The linker map is not byte-reproducible. It embeds rustc's random temporary directory for
the synthesized `symbols.o`, nineteen times in the current build. Nothing that gets flashed
contains it.

Reproducibility is claimed for one machine rebuilding one revision. Nothing here shows that
two different machines, or the same machine after a toolchain update, produce identical
bytes.

A dirty tree stamps HEAD's commit time while the sources differ from HEAD. The `-dirty`
suffix in the version field flags it, and CI rejects a dirty tree outright. The manifest's
`source_dirty` and that suffix count different things, because `git status --porcelain`
counts untracked files and `git describe --dirty` does not, so a tree with only untracked
files reports one and not the other.

`CONFIG_APP_REPRODUCIBLE_BUILD` remains off, deliberately. It would remove the date and
time entirely, which would delete provenance that already works.
