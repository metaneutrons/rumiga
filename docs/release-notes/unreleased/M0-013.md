# M0-013: Enforced Conventional Commit Policy

- Status: Unreleased
- Change type: Changed
- Task: M0-013
- Audience: Contributors and maintainers

## Summary

Rumiga now validates Conventional Commit messages through one repository-owned
Rust implementation. The local commit hook, pull-request commit range, pull-
request title, direct `main` push range, and required aggregate use the same
policy.

## User And Operator Impact

None. Emulator runtime behavior, media formats, and device firmware behavior
are unchanged. Contributors receive precise local and hosted diagnostics for
invalid commit history.

## Compatibility And Migration

Existing history is not rewritten. New commits use
`<type>(<optional-scope>)!: <description>` with a supported lowercase type and
scope; bodies start after a blank line. WIP, autosquash, and merge commits must
be resolved before promotion.

## Verification

Focused Rust tests cover valid and invalid grammar. The canonical
`cargo +1.97.1 xtask ci --gate commits` command validates real Git objects, and
the workflow topology test requires the hosted job in the aggregate.

## Known Limitations

The validator proves syntax and range coverage, not semantic scope quality or
review approval.
