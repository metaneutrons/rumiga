# M1-007: Platform Capabilities And Typed Errors

- Status: Unreleased
- Change type: Added
- Task: M1-007
- Audience: Embedded integrators and maintainers

## Summary

Platform contracts are now versioned and describe what a backend supports. Failures are
typed, with `Unsupported` explicit, and backpressure is reported on the success path
rather than as an error.

## User And Operator Impact

A display failure is no longer silent. `VideoOutput::present_frame` returned nothing and
the desktop adapter discarded the result of the window update, so a dead window looked
exactly like a healthy one: the shell kept emulating and kept measuring a frame rate for
frames that never reached a display. The shell now reports the failure and stops the
loop.

The startup summary reports the contract version, the video bounds, whether the backend
can report backpressure, and whether audio is present. What the backend offers is visible
before the first frame.

A backend built against a different contract version is rejected at startup rather than
failing later inside an unrelated call. The message names both versions.

Rendered output is unchanged. A 1200-frame A1200 capture keeps the digest recorded for
M1-013.

## Compatibility And Migration

`rumiga-platform` gains `CONTRACT_VERSION`, `PlatformError`, `PlatformCapabilities` with
its per-service descriptors, the `CapabilityReport` trait, `FramePresentation`, and
`SamplesQueued`.

`VideoOutput::present_frame` returns `Result<FramePresentation, PlatformError>`. An
implementation returns `FramePresentation::Presented` when the frame reached the display,
`FramePresentation::DroppedForBackpressure` when the display was not ready, and an error
only when something failed. Dropping under backpressure is a success.

`AudioOutput::queue_samples` returns `Result<SamplesQueued, PlatformError>`. A backend
takes what fits and reports the remainder in `SamplesQueued::rejected`. Partial
acceptance is normal operation.

`StorageError` is removed. The `Storage` trait uses `PlatformError`, which covers the same
cases plus `ReadOnly`. No backend implemented `Storage`, so no implementation needs
porting. The desktop shell's own `storage::StorageError` is a REST-layer type and is
unaffected.

A backend must implement `CapabilityReport`. `DesktopBackend::new(max_width, max_height)`
provides the desktop report; it takes the framebuffer bounds so the reported maxima cannot
drift from the buffer the shell allocates.

## Verification

The two states this task is about are exercised against a backend double, because the
desktop backend can produce neither: it has no audio at all, and minifb either presents or
fails rather than refusing. The double reports `audio: None` and returns `Unsupported`
when called anyway, and refuses a frame so the dropped outcome is reachable and
distinguishable both from a presented frame and from an argument error.

The version rejection was verified with a probe rather than only asserted. A desktop
backend temporarily reporting a version seven ahead of the contract made the shell exit
with status 1, name both versions, and write no capture.

Desktop capability tests hold the report to what the adapter actually implements, including
that it admits it cannot report backpressure.

## Known Limitations

The desktop backend reports no backpressure, so its dropped-frame count stays at zero. The
capability flag says so; a zero count is not evidence of health.

`AudioOutput` and `Storage` still have no implementor. They now describe their failures in
the shared error model, which is a smaller claim than being implemented.

`AudioCapabilities::max_queued_frames` describes a bound that nothing enforces yet. The
bounded queues and high-water marks belong to M1-008.

Capabilities are not published over REST or the serial protocol. Aligning the control
surfaces with the capability set is M8-008.

The descriptor covers video, audio, input, and storage. The remaining services in the
architecture's contract table, among them block media, network link, lifecycle, and
telemetry, are later milestones and have no capability fields yet.
